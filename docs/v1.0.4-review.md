# v1.0.4 review notes

## Scope

Based on released v1.0.3 (`474334735e72e2deeb276e2c81c017d865ef0725`). No changes to monthly traffic migration, finance, Transit, owner preview, Server or Agent. Independent version source remains `komari-theme.json`.

## Safe area

`index.html` already enables `viewport-fit=cover`, standalone capability and `black-translucent` status bars. The sticky header previously had no inset. Header alone now owns top padding from `env(safe-area-inset-top, 0px)`; its inner toolbar stays 56px. No body padding, device/version sniffing or second offset is introduced. On ordinary zero-inset viewports the layout is unchanged; scrolling retains the inset inside the sticky header.

Playwright covers desktop, mobile and a 390x844 standalone simulation with an injected 47px CSS inset, before/after scroll. This verifies geometry, not an actual iOS 27 Safari/A2HS launch or hardware-provided env value. Real-device smoke testing remains recommended. No snapshot baselines changed.

## Native authentication audit and fallback

Read-only references:

- [Server 1.5.0 login](https://github.com/komari-monitor/komari/blob/1.5.0/web/api/public/login.go): native POST `/api/login`, optional `2fa_code`, HttpOnly `session_token` cookie; no theme-side credentials.
- [Official frontend 1.5.0 routes](https://github.com/komari-monitor/komari-web/blob/1.5.0/src/routes.ts) and [LoginDialog](https://github.com/komari-monitor/komari-web/blob/1.5.0/src/components/Login.tsx): no standalone `/login`/return-url route; success defaults to `/admin/dashboard`.
- This repository bundles official frontend commit `ebfbd3e079f8777a746276fe67429b519024f7c7`, recorded in `public/admin-app/komari-admin-source.json`. Its `AccountContext.tsx` uses `/api/me` and `logged_in`; its `Login.tsx` uses native `/api/login`, `/api/oauth` and defaults to `/admin` after password login. No bundled React code or dependencies were rebuilt.

The theme re-verifies the session on admin click through the existing auth service. Authenticated users go directly to `/admin`. Guests/errors go to `/admin-app/index.html?__komari_route=%2F`; the existing narrowly allowlisted bridge now also accepts exact `/`, allowing the bundled official **public homepage** to render rather than entering the admin route first. This is a theme bridge parameter, not an invented upstream login parameter.

Fallback UX: guests click the native homepage's visible Login button once more, then use the unchanged native password/2FA/OAuth flow. Private-site native login auto-open remains upstream behavior. No hidden-button click automation, new authentication UI, stored password/token, or return-url state is introduced. Native success enters admin. The sync script emits the same bridge so future asset sync preserves the fix.

Tests exercise logged-in navigation, guest navigation without any `/admin` document before login, rendering the real bundled native dialog, and native password-success navigation (the server response is mocked; this is not a live credential/session integration test).
