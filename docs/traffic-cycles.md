# v1.2.1 · 每节点独立流量周期

## 设置与展示范围

管理员登录，打开页头「Enhanced 管理 → 节点与卡片 → 流量周期」。主题自带兼容后台的托管设置入口可桥接到此五分类编辑页；Komari 服务器内置 `/admin/theme_managed` 保持原生配置编辑器，不由主题接管。

每行对应一个节点：名称、UUID、每月 1–31 日的重置日、当前周期起止、下次重置日期、当前周期已用量。选择日期后逐台保存，成功提示以服务端读回为准。无需手填 JSON 或修改配置文件。未配置节点明确显示「未设置」，不默认按每月 1 日。

**前台卡片和列表不显示重置日期、周期时间范围、距重置天数、倒计时或相关额外图标**；不添加流量模块、不增加卡片高度。沿用原流量进度、已用/剩余/百分比布局，仅更换计算周期。未配置或数据不足时不显示假余额或假 0 GB，仍可显示原始累计上传/下载。

## 日历与节点隔离

- 时区为 `Asia/Shanghai`，每个重置日的 `00:00:00` 切换。
- 区间为 `[开始时间, 下次重置时间)`；结束边界只属于新周期。
- 29/30/31 日在短月份取当月最后一天，下个月恢复**原设定日**，不是从月末连续加 30 天。
- 以节点 UUID 为键；节点改名不丢设置。修改 A 仅重新查询 A，不能改变 B 的配置或当前周期。
- 清除某节点重置日只删除该节点的周期配置，不清空节点记录、其他节点配置或原始累计计数器。

配置写入 Komari 原有 `Enhanced` 托管主题设置的 `trafficCycleConfig` 字段，不新增官方节点数据库字段，不存普通 tags，不依赖 localStorage。其他主题字段、未知设置和其他节点保持原样。损坏/未知格式的周期配置会阻止覆盖，不会被静默替换为空表。

v1.2.0 源码中没有仍在启用的自然月清零任务；本版不恢复月初默认、不删除旧缓存，也不让旧统一月度字段驱动周期计算。

## 统计依据

使用 Komari 1.6.0 原生 `public:queryMetrics`，按 UUID、开始/结束时间查询：

- `traffic.up` / `traffic.down` 使用 `sum`，保留服务端已有的重启、归零、回绕和异常增量处理。
- `net.total.up` / `net.total.down` 用作可靠周期起点历史的覆盖证据，不用两个累计端点简单相减冒充全周期流量。
- 沿用原 `traffic_limit_type`：上传、下载、双向合计、取较大方向及既有取较小方向模式。
- 不清零 `net_total_up` / `net_total_down`；不清空数据库，不修改 Agent、历史记录或累计图表。
- 共享 UUID/日期/权限上下文的订阅和缓存，周期刷新；移除最后一个订阅者会停止计时器并取消其未完成查询。

边界按原生采样/聚合时间归属，不是运营商逐字节计费系统；采集间隔内的实际网络字节时间不能由主题反推。该展示不代替服务商账单。

## 数据不足与后端保留范围

缺少起点附近的可靠历史、内部历史明显中断、最后采样过期、协议不支持、异常/重复样本或只剩不能对齐上海午夜的粗粒度历史时，显示「数据不足」。**缺失不是零**，也不能用当前累计总量替代本周期用量。

服务端必须保留覆盖完整周期及起点证据的小时或更细粒度历史。Komari 1.6.0 源码中小时保留配置 `metric_rollup_hour_retention_hours` 默认是 `600`；这不保证覆盖每一个完整月度周期。管理员应在服务端确认保留范围，例如采用 `800` 小时的小时级保留并确认磁盘预算；主题不会擅自修改这一全局设置。更粗的日级历史可能无法精确对齐 `Asia/Shanghai` 午夜，因此不能为了显示数字而强行按日求和。

延长保留时间只保护之后仍存在的数据，不能补回已经删除的历史。新安装、Agent 离线较久或刚开始保留指标的节点，可能要等到有完整、可靠的周期历史后才能显示周期配额。原始累计值和图表继续保留。

## 保存、升级与回退

保存前强制确认管理员会话，读最新设置、检查目标字段/UUID 冲突；写入整份设置后再次精确读回。提交后遇到网络错误也会读回确认，不重试强行覆盖。原生 API 没有真正的多请求事务/CAS，多管理员应避免同时编辑；检测到冲突会停止并要求重新加载。

从 v1.2.0 / v1.1.1 原位升级时保持 `short=Enhanced`。只补入新声明的默认配置，不迁移/重算原始历史。使用 Full 包时按 [统一升级/备份/回滚](full.md) 操作。回退旧主题不会清除原始流量，但旧版本不会消费新的独立周期设置；不要把旧版累计配额显示误认为本版周期口径。

## 测试边界

日历、节点隔离、配置保护、重启/回绕、计费模式和缺失历史有单元测试；四种卡片尺寸、亮暗/移动端、无倒计时、五分类保存/重新加载有浏览器 fixture 测试。原生集成启动私有 loopback Komari 1.6.0，通过真实主题上传、RPC、后台编辑与读回验证。

`tests/full/seed_traffic_fixture.py` 仅向明确隔离的 `test-results/full/native-lab-*` 指标库插入**标记的合成历史 fixture**，不伪造 RPC 响应、不更改表结构、不删除已有记录；保存前后对既有测试历史做指纹比较。该 fixture 不是生产流量、服务商账单或真实公网 traceroute 验证。Komari 1.6.1 未实测。
